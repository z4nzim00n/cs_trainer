## Жёсткие правила

1. **Один файл — одна программа.** `using ...`, единственный класс
   `Program` со статическим `Main`, все вспомогательные типы — в том же
   файле.
2. **Скелет компилируется.** `Program.cs` для задач «напиши с нуля»
   должен собираться, даже если печатает `TODO`. Заглушки типов и методов
   добавляй в скелет. Исключение — две задачи «исправь ошибку» в
   `01_basics`: там код намеренно сломан.
3. **Вывод программы — только ASCII.** Никаких русских строк в
   `Console.Write`/`WriteLine`. Русские комментарии в коде допустимы:
   файлы в UTF-8.
4. **Точный вывод.** Тесты сравнивают байты после нормализации
   `\r\n` → `\n`. В README явно указано, есть ли перенос строки в конце.
   `Console.WriteLine` = `\n`, `Console.Write` = без `\n`.
5. **Никаких комментариев в `Solution.cs`.** Как в Школе 21. Комментарии —
   только в `SolutionCommented.cs` и в `// TODO` скелета.
6. **Стиль.** K&R-скобки, отступ в 4 пробела (как в Visual Studio),
   осмысленные имена. Файл должен проходить `csc -warn:4` без
   предупреждений.
7. **Детерминированный вывод.** Потоки синхронизируй через `Join`,
   `Task.WaitAll` или отдельные ячейки результата. Не полагайся на
   порядок обхода `Dictionary` и планировщик.
8. **Культура.** Для `double.Parse` и `ToString("F2")` используй
   `CultureInfo.InvariantCulture` — иначе на русской Windows появится
   запятая.
9. **Крайние случаи в тестах.** Пустой ввод, `n = 0`, отрицательные
   числа, деление на ноль, отсутствующий файл.

## `run_testsN_M.sh` — шаблон

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")"
source ../../../scripts/lib.sh

compile

run_case "2 2" $'4\n'
run_case "-4 4" $'-16\n'
run_case_devnull $'0\n'

if [ -z "$FAILED" ]; then
  echo "Все тесты пройдены"
else
  echo "Есть проваленные тесты"
  exit 1
fi
```

### API `scripts/lib.sh`

- `compile` — собирает `$SOURCE_FILE` (по умолчанию `Program.cs`) в
  `.build/app.exe`. Дополнительные флаги `csc` передаются аргументами.
- `run_case "вход" "ожидание"` — вход через `printf` (добавляет `\n`).
- `run_case_noeol "вход" "ожидание"` — без завершающего `\n`.
- `run_case_devnull "ожидание"` — пустой stdin (EOF сразу).
- `run_case_args "аргументы" "вход" "ожидание"` — запуск с аргументами.
- `check_file "путь" "ожидание"` — проверяет содержимое файла,
  созданного программой.

Ожидание — точные байты:

```bash
run_case "2 2" $'4\n'          # WriteLine
run_case "2 2" "4"             # Write
run_case $'a\tb\nc' $'3\n'     # табы и переводы строк
```

### Файловые задания

Создай файлы до вызова `run_case` и удали их через `trap`:

```bash
trap 'rm -f input.txt output.txt' EXIT
printf 'hello\n' > input.txt
run_case "input.txt" $'hello\n'
check_file "output.txt" "hello"
```

Относительные пути считаются от папки задания.

## Порядок проверки

```bash
cd tasks/<раздел>/<задание>
SOURCE_FILE=Solution.cs bash run_testsN_M.sh
SOURCE_FILE=SolutionCommented.cs bash run_testsN_M.sh
rm -rf .build
```

Оба запуска должны напечатать `Все тесты пройдены`.

Проверка скелета:

```bash
SOURCE_FILE=Program.cs bash -c 'source ../../../scripts/lib.sh; compile'
```

Для задач «исправь ошибку» эта команда может падать — это ожидаемо.

Проверка предупреждений:

```bash
csc -nologo -langversion:latest -warn:4 -out:.build/check.exe Program.cs
```

Компилятор не должен выдавать предупреждений.

## theory.md — что писать

Хороший разбор содержит:

1. **Идею** — зачем нужна тема, где пригодится.
2. **Минимальный пример** на C# в `~~~csharp`.
3. **Разбор** — что делает каждая строка.
4. **Таблицу** сравнения или шпаргалку.
5. **Частые ошибки** — 3–5 пунктов с последствиями.
6. **Крайние случаи** — что будет при `0`, `null`, пустой строке.

Не пересказывай учебник. Пиши то, что нужно именно для этого задания.

## Генератор из спецификаций

Все 71 задание собраны из `specs/*.spec` скриптом `build.js`. Спецификация
удобна для массового создания заданий: в ней нет JS-экранирования, C#-код
и Markdown лежат как есть.

Формат спецификации:

```text
@@TASK
section: 05_arrays_lists
dir: 01_list_sum_average
num: 5_1
title: CS_05_01. Сумма и среднее
topics: `List<int>`, `for`, среднее, `F2`
input: `n`, затем `n` целых чисел
@@DESC
...
@@EXAMPLES
| Входные данные | Результат работы |
| ------ | ------ |
| `3`<br>`1 2 3` | `Sum: 6` |
@@THEORY
...
@@TESTS
| `3\n1 2 3` | `Sum: 6\n` |
@@CASES
run_case $'3\n1 2 3' $'Sum: 6\n'
@@MAIN
using System;
...
@@SOLUTION
using System;
...
@@COMMENTED
using System;
...
@@END
```

Пересборка:

```bash
node build.js
```

Генератор — внутренний инструмент. Для прохождения заданий он не нужен.
Если правишь задание вручную, помни: следующая сборка перезапишет файлы
из спецификации.
