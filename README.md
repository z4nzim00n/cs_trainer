# C# Trainer — путь с нуля

Тренажёр по C# для тех, кто раньше не писал на этом языке. 13 разделов,
71 задание: от `static void Main()` до LINQ, задач и перегрузки операторов.

Каждое задание — отдельная папка с условием, теорией, тестами, заготовкой,
эталонным решением и решением с комментариями. Всё проверяется побайтовым
сравнением вывода, поэтому «почти правильно» не засчитывается.

---

## Быстрый старт

### 1. Что нужно

Компилятор C#. Подойдёт любой из вариантов:

- **Visual Studio Build Tools / Visual Studio** — в поставке есть
  `csc.exe` (Roslyn). Отдельный .NET SDK не обязателен;
- **.NET SDK** — тогда можно собрать через `dotnet`, но скрипты тренажёра
  ищут именно `csc`.

`scripts/lib.sh` ищет `csc` в `PATH`, затем в стандартных папках
Visual Studio:

```text
.../MSBuild/Current/Bin/Roslyn/csc.exe
```

Если компилятор лежит в нестандартном месте, задайте переменную `CSC`:

```bash
export CSC="/c/Program Files (x86)/Microsoft Visual Studio/.../csc.exe"
```

### 2. Как проходить задание

Из корня `cs_trainer` в Git Bash:

```bash
cd tasks/01_basics/01_hello_world
bash run_tests1_1.sh
```

Но сначала — руками:

```bash
csc -nologo -langversion:latest -out:app.exe Program.cs
./app.exe
```

Ожидаемый вывод:

```text
Hello, C#!
```

> В Git Bash используйте **дефисные** опции (`-nologo`, `-out:`), а не
> слэшевые (`/nologo`): иначе bash примет `/nologo` за путь.

Порядок работы:

1. Открой `README.md` — там условие и примеры.
2. Прочитай `theory.md` — короткий разбор темы.
3. Открой `Program.cs`, найди `// TODO` и допиши программу.
4. Запусти программу и сравни с примерами.
5. Проверь себя автотестом: `bash run_tests1_1.sh`.
6. Если не получается — посмотри `Solution.cs` и `SolutionCommented.cs`.

### 3. Проверка всех заданий

```bash
cd cs_trainer
bash scripts/run_all.sh --solution
bash scripts/run_all.sh --commented
```

Обе команды должны напечатать:

```text
Пройдено: 71/71
```

### Что внутри по разделам

**01. Основы.** `using System`, класс `Program`, `static void Main`,
`Console.WriteLine`, переменные, исправление намеренно сломанного кода,
обмен значений.

**02. Ввод и вывод.** `Console.ReadLine`, `int.Parse`, `Write` против
`WriteLine`, `Split`, интерполяция строк, смешанный ввод.

**03. Выражения.** Целочисленное деление, остаток, `double`, приведение
типов, `Math.PI`, логические операторы.

**04. Циклы.** `for`, `while`, `do-while`, `foreach`, `break`/`continue`,
цифры числа, FizzBuzz, XOR.

**05. Массивы и List.** `int[]`, `List<T>`, `Add`, `Count`, `Sort`,
`Reverse`, `HashSet`, `string.Join`, циклический сдвиг.

**06. Строки.** `Length`, `char`, `ToUpperInvariant`, `Split`,
`StringSplitOptions`, разворот, палиндром, шифр Цезаря.

**07. Классы.** Поля, конструкторы, методы, `readonly`, `ToString`,
наследование, `virtual`/`override`, абстрактные классы.

**08. Коллекции.** `Dictionary`, `TryGetValue`, `HashSet`,
`SortedDictionary`, подсчёт частот, группировка, инверсия словаря.

**09. Ошибки.** `try`/`catch`, `DivideByZeroException`, `TryParse`, своё
исключение, `IDisposable` и `using`, выход за границы массива.

**10. Файлы.** `File.ReadAllText`, `WriteAllText`, `Copy`, `ReadAllLines`,
разбор чисел, подсчёт слов, статистика файла.

**11. Потоки.** `Thread`, `Start`/`Join`, `lock`, `Task.Run`,
`Task.WaitAll`, `Interlocked`, параллельная сумма.

**12. Bootcamp.** Простые числа, кофейный автомат, статистика,
гистограмма, поворот матрицы, сумма и диагональ.

**13. Advanced.** Дженерики с `IComparable<T>`, сортировка лямбдой, LINQ
(`Where`, `Select`, `Sum`), перегрузка оператора `+`.

## HTML-инструменты

### trainer.html

Просмотрщик заданий. Открой файл в браузере, нажми «Выбрать папку проекта»
и укажи папку `tasks`. Слева появится дерево разделов и заданий.

Что можно смотреть:

- условие (`README.md`);
- теорию;
- тесты;
- заготовку `Program.cs`;
- решение `Solution.cs` и решение с комментариями
  `SolutionCommented.cs`.

Настройки темы и размера шрифта сохраняются в `localStorage`.

После каждого ответа показывается разбор. Отдельный блок — дженерики
и LINQ (раздел 13).

## Как проверяются задания

Автотест собирает файл и сравнивает **точные байты** вывода. Переводы
строк `\r\n` от Windows-консоли нормализуются в `\n`:

```bash
SOURCE_FILE=Solution.cs bash run_tests5_1.sh
```

- `run_case "вход" $'ожидание\n'` — вход через `printf`, ожидание
  в ANSI-C кавычках;
- `run_case_noeol` — без завершающего `\n`;
- `run_case_devnull` — пустой stdin;
- `run_case_args` — аргументы командной строки;
- `check_file` — файл, созданный программой.

Файловые задания создают временные файлы в папке задания и удаляют их
через `trap`.

Для чисел с плавающей точкой используется
`CultureInfo.InvariantCulture`: иначе на русской Windows `double`
напечатается с запятой и тест не совпадёт.

## Частые проблемы

**Компилятор не найден.** Установите Visual Studio Build Tools с
компонентом .NET или .NET SDK. Проверьте, что `csc` доступен в `PATH`,
либо задайте `CSC` с полным путём.

**`/nologo` превращается в путь.** Git Bash преобразует аргументы,
начинающиеся со слэша. Используйте `-nologo`, `-out:app.exe`,
`-langversion:latest`.

**Вывод отличается переводом строки.** `Console.WriteLine` добавляет
`\n`, `Console.Write` — нет. Тесты побайтовые: проверьте, нужен ли
перевод строки в конце.

**Среднее печатается с запятой.** Добавьте
`using System.Globalization;` и используйте
`value.ToString("F2", CultureInfo.InvariantCulture)`.

**Логическое значение печатается не так.** C# выводит `True` и `False`
с заглавной буквы, а не `true`/`false`.

**Потоки дают разный вывод.** В заданиях порядок фиксируется через
`Join`, `WaitAll` или отдельные ячейки результата. Не полагайтесь на
планировщик.

**Кириллица в выводе.** В заданиях вывод намеренно ASCII. Русские
комментарии в коде допустимы (файлы в UTF-8), но строки для тестов —
только латиница.

**Файловое задание не находит файл.** Относительный путь считается от
текущего каталога. Запускайте тест из папки задания.

**Хочу пересобрать задания из спецификаций.** Из корня:

```bash
node build.js
```

Спецификации лежат в `specs/`. Это внутренний инструмент, для прохождения
заданий он не нужен.
